**Procedure to change a price without missing a spot:**

1. Confirm the new number with the clinic and write it down once (tier table, package, unit, member rate).
2. Edit the page table at the `file:lines` in the map. If the floor (lowest number) changes, also edit any `price` fallback literal in that file (microneedling:209; botox:226 and rf-microneedling-prp:200 are dead but keep them honest or delete them).
3. Edit the matching printable rows, add/remove Members rows to match the page, and bump `price-list-printable.html:299` to the new effective month.
4. Admin → Services → service → Price: set the string to the new floor in the existing format (`Starting at $X/unit|session|area|vial`). For IV drips/NAD+ use Admin → IV Therapy. Load the category page once afterwards to confirm the card updated.
5. If a tier/product is renamed, grep the old name across everything: `grep -rn "Deluxe" app components lib price-list-printable.html`.
6. Update `lib/content/placeholder-services.ts` (and `supabase/seed.sql` if you ever reseed) — or remove prices from placeholders entirely (see below).
7. Check `app/(public)/membership/page.tsx:28-29,47-50` — does every free item still exist under that exact name, and do the perks still match any "Members" rows on service pages?
8. Verify: `grep -rnE '\$[0-9]' "app/(public)" lib components/sections price-list-printable.html`; after deploy, curl the category page, the service page, and `/price-list` and compare.
9. Commit the page, printable, and placeholder edits together; do the admin edit the same day.

# 4. Contested findings (use judgment)

- **Supabase Storage cache TTL (technical F8).** Finding: uploads omit `cacheControl` (`app/api/admin/assets/upload/route.ts:31-36`), so assets are `max-age=3600` and "re-downloaded hourly". One verifier refuted the mechanism: the origin sends strong ETags and answers `If-None-Match` with 304 (near-zero bytes), and Smart CDN (`x-smart-cdn: true`, Pro plan) caches at the edge regardless of the header; the other kept it as low. Both agree the one-line change is harmless and that hashed/immutable filenames would break the admin's upsert-by-name flow and the 60 hardcoded URLs. **Decision for you:** add `cacheControl: '2592000'` (30 days) to the upload options and, if desired, backfill existing objects via `storage.from('media').update(path, body, { cacheControl })`; use `?v=N` on hardcoded URLs if you ever replace an asset in place. Expect fewer revalidation round-trips, no ranking effect, no meaningful egress change — F2 (file sizes) is the real lever.

- **Preconnect to Supabase + 1,115 inline style props (technical F13).** Both verifiers refuted the preconnect half: React already emits `<link rel="preload" as="image">` for the Supabase logo as the first `<head>` element (warming the origin at the same instant), HTTP/2 reuses the socket, and the proposed `crossOrigin=""` would open an anonymous connection that no-cors `<img>`/`<video>` cannot reuse. **Decision:** skip preconnect; fold the 978 inline `fontFamily` declarations into the fonts fix (Medium 1) where they are a prerequisite, and delete the 545 Montserrat ones outright (Tailwind preflight already sets Montserrat as `--default-font-family`).

- **Dollar figures in meta descriptions (onpage F2 vs pricing F12).** One verifier: never hardcode prices in static metadata (two price sources already disagree). Another: Google explicitly encourages price in descriptions, and the pages target "Botox cost Pasadena". Reconciled position: no literal dollar figures in `export const metadata`; if you want price in a snippet, convert that page to `generateMetadata` and interpolate the single pricing source after Section 1 Option B lands.

- **Testimonials: relabel vs remove (onpage F11 vs SD-11/F04).** Relabeling "Botox & Dysport" → "Botox & Xeomin" is correct only if the quotes are from real clients. Verifiers lean toward removal because the identical three entries exist in code, fallback and the seeded DB. Owner must answer.

- **Do not add `aggregateRating`/`Review` markup** to the LocalBusiness or Service nodes, or embed a Google/Facebook reviews widget: Google's review-snippet policy excludes self-serving reviews, and today's testimonials are placeholders (`Testimonials.tsx:6-25`, `seed.sql:212-235`).

- **Do not write "at Slynn Wellness, Pasadena" into alt text**, do not stamp "in Pasadena" onto all 15 H1s, do not add city lists to every service page, and **do not create per-city doorway pages** — these are the exact keyword-stuffing patterns Google's spam policy names.
